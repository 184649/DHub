# 改善項目の対応台帳

対象: develop `3ab0e184233fac117836b780c676869964e29d95` からのプレビュー専用ブランチ。2026-10-17 時点。
「実装済み」はソースの状態であり、すべての Windows GUI 受入試験を完了した意味ではありません。

## 実装済み

| 項目 | 対応と主な検証 |
|---|---|
| split の途中破損で有効な一覧が消える | 全候補を解析・検証してから反映。破損・競合は読取専用にする。実ファイル回帰試験。 |
| 分離 OFF なのに古い split が復活 | OFF 時は split の読込前に終了。回帰試験。 |
| 正本欠損・破損時の回復 | `.bak` の検証、回復不能時の自動空保存禁止。読込だけで保存しない。 |
| 保存途中の喪失 | 同一フォルダーの一時ファイルを flush して置換、backup 保持。旧 safe-save OFF でも安全な経路を使用。 |
| 外部編集・多重書込み | 読込時と保存前の fingerprint、不明確な保存失敗後は読取専用。未観測の同時変更を完全に防ぐ OS ロックではない。 |
| combined / split の競合 | 件数・名称・起動先・引数・設定・metadata の差分を表示。使用候補の明示選択。 |
| 回復前の原本保全 | 元ファイル一式を SHA-256 検証付きで `PreservedSnapshots` に保全。通常 backup の整理対象から分離。 |
| 起動成功後に保存失敗を起動失敗と表示 | Shell 要求と履歴保存を別の結果にする。履歴再保存で起動要求を繰り返さない。 |
| ログ失敗で元の例外が隠れる | ログの失敗を隔離。workspace は成功した要求だけ記録し、重複同時実行を抑止。 |
| Memo 編集値の欠落 | 編集結果に Memo を反映。 |
| 文字入力中の Delete / Enter / Ctrl+C 奪取 | リストがフォーカスされている場合に限定。入力部品は除外。 |
| 無条件の重複削除と workspace 参照破損 | URL・引数・開くアプリを含む recipe を保持。metadata の一致も要求し、削除時は参照 ID を再割当。重複 ID・壊れた参照は拒否。 |
| Windows 引数の引用 | 埋込み引用符・末尾バックスラッシュを正しく quote。回帰試験。 |
| 直接お気に入り popup | 左クリックで先頭 20 件、SortOrder→Name 固定。同名は種類・場所・引数を表示、全件導線。 |
| 元 file / folder / URL / .lnk / .url の維持 | 元 recipe の起動を継続。リンク先の独自再構成は行わない。 |
| フォルダー参照 | 非同期 scan、監視、immutable snapshot、分類フォルダーを開く入口。非表示・解除は非破壊。 |
| overflow / 全件検索 | popup 上限を明示し、登録全件・取得済み source 全件へ移動。source 走査自体の上限は明示し、原フォルダーを開ける。 |
| 読込中・空・全非表示・offline・検索 0 件 | 状態を表示。手動登録は独立して利用可能。 |
| 古いメニューからの誤起動 | recipe と source revision の再確認。監視済み変更・削除・同 path 置換で古い snapshot を拒否。監視不能は直接起動を停止。 |
| 不変 refresh で全項目が無効になる | 内容が変わらない refresh は revision を保持。再接続は別 revision。 |
| UI の同期ファイルアクセス | link status / icon を並列数制限付き非同期 cache に変更。古い検査結果の混入を防止。 |
| 大量フォルダーの menu 作成 | 子要素を index 化、階層を開いた時に遅延作成。 |
| keyboard / focus | 左クリック popup の native owner と foreground 制御、Escape で前画面復帰。実画面確認は残る。 |
| 検索画面再表示・同名用途の識別 | 閉じたウィンドウ参照を破棄。全件に recipe と tooltip、可変高の行。 |
| 独立バー | 同じ popup を使用、初期 OFF、常時最前面にしない。表示状態に合わせて切替。 |
| 安全な updater | 許可済み公式 HTTPS、SHA-256、サイズ上限、zip traversal / link / duplicate 拒否。実ソース回帰 50 件。 |
| updater の終了・置換・回復 | staging-ready / proceed の原子的合図、正確な PID を待機し kill しない。backup + File.Replace、部分失敗 rollback、BOM manifest 対応。 |
| 更新後の profile 消失 | `--data-dir` を updater 経由で引き継ぐ。準備失敗時はアプリを閉じない。 |
| プレビューの通常版への誤更新 | 別バージョン・保存先・preview guard。正式配布時だけ明示 version を設定。 |
| サンプルと最初の入口 | 明示追加で実ファイル・専用フォルダー・公式URLを固定。安定ID＋同一recipeで重複防止。既存編集を保持。新規は一覧起動、既存概要設定は1操作で変更。保存・削除rollbackを回帰試験。 |
| 起動と確認手順 | README と検証書、既設 SDK 10 を選択、単一 Windows job のブランチ限定 CI。 |

## 保留・残る受入確認

| 項目 | 理由・次の確認 |
|---|---|
| Windows GUI / 実 Shell / 実トレイ | CI はコンパイル・console 回帰。対話 Windows 環境で手順書の実操作が必要。 |
| 高 DPI・複数画面・fullscreen・focus | バーは初期 OFF。表示・復帰・キー操作の実機確認が必要。 |
| toolbar より速いという評価 | 入力数・操作時間・誤選択数の利用者測定が未実施。優位性は未断定。 |
| SMB切断・OS電源断・同時変更の網羅 | 合成 IO と監視試験はあるが実ネットワーク、電源断、未観測 TOCTOU を保証しない。 |
| 保存形式の全面刷新 | single source + 派生 split / 世代 manifest は未採用。既存の分離設定と外部編集の互換性を優先。 |
| Authenticode | SHA-256 は完全性確認で署名された発行者の証明ではない。署名導入は別判断。 |
| 正式配布と更新 E2E | merge / release / 実際のインストール置換は未実施。プレビュー通常版更新を止めた状態で検証。 |

## 採用しない方針

- taskbar への注入・改造、利用者の元 shortcut の書換え・削除。
- 読込失敗の無視、空データでの自動初期化、対象文字列だけでの重複削除。
- 追加操作で fixed favorites の順番を変えること、件数上限を隠すこと。
- 検証前に「旧 toolbar を上回る」「実機動作確認済み」と扱うこと。
