# 1.1.4-preview.1: 目的のものを直接開く試作

この版は使いたさ・日々の時短をまだ実証していない小さな試作です。Windows の画面操作、実 Shell 起動、DPI、複数画面は実機で確認してください。回帰テストと CI の結果は、それらの確認を代替しません。

## 日常の流れ

1. Ctrl+Shift+Space で一覧を開きます。お気に入りは従来の登録順を保ち、入力せず選べます。
2. 必要なら名前や場所を入力します。名前の完全一致・前方一致を、パスやメモの一致より先に表示します。
3. 行の「開く」、Enter、または行のダブルクリックで対象を開き、一覧は隠れます。Esc・他画面への切替でも隠れます。

直接登録、連携フォルダー内の項目、任意に保存した組合せを同じ一覧で探せます。作業名を選ぶ別階層、概要・件数ダッシュボード、強制的な分類はありません。検索結果は100件ずつ表示し「さらに表示」で続きへ進めます。

## 登録

- 「追加」を押してから一覧へファイル／フォルダーをドロップするか、パス・HTTP(S) URL を貼り付けて保存します。追加中は他の画面へ切り替えても一覧を表示したままにし、Escで追加を終了します。フォルダーを落としても中身を一括登録しません。
- 新規の直接登録はお気に入りとして追加します。名前は対象から推定します。名前・起動方法などを変える場合は管理画面を使います。
- 1回の追加は100件まで。同じ起動先・引数・開くアプリの登録は追加しません。異なる起動レシピは別登録です。記録するだけで対象は起動しません。
- 「組合せを登録」は、既に登録した項目から本人が選んで保存する機能です。全PCの監視や自動収集はしません。

## まとめて開く

組合せは通常の項目と同じ一覧に「まとめて開く・N件」と表示します。最初の起動時に全対象と起動方法を確認します。同じ内容についてはDHubを終了するまで確認を省略し、内容変更／アプリ再起動時には再確認します。入力の勢いで確認されないよう、確認画面に既定のEnterボタンはありません。

一括起動の重複要求は抑止します。起動待ち時間中に組合せ・起動方法が変わったら残りを止めます。ウィンドウ配置や編集途中の状態を復元する機能ではありません。

## 連携と安全性

- 登録済みの連携フォルダーだけをバックグラウンドで読みます。直接登録は読込完了を待たず表示します。
- 元の .lnk / .url をそのままShellで起動し、リンク先へ解決・書換えしません。リンク先そのものが失われているかは、この一覧だけでは判定できません。
- 読取不可・変更中・監視不可のスナップショットからは起動せず、状態を表示します。登録元フォルダーを開く入口も残します。
- 連携項目の表示は合計2万件まで。各登録元にも走査件数・深さの上限があります。上限や読取不能は表示し、登録元から全件へ到達できるようにします。再解析ポイントはたどりません。
- 同じ対象が複数の登録元にある場合、出所や起動設定を失わないよう別の行として残します。1行の起動から別の重複行を連鎖起動しません。
- 非同期更新で検索語は消しません。選択対象のIDと起動レシピが変わったら、自動で別の対象を選択せず、利用者の選び直しを待ちます。

## 既存データ

保存形式・既存設定・お気に入り・登録順・組合せは維持します。トレイ常駐、ホットキー衝突時の復帰、同一プロファイルの二重起動制御、自動更新停止も維持します。既存データの自動移動はしません。

最初は新しい検証用保存先 `--data-dir "$env:TEMP\DHub-1.1.4-QA"` で起動してください。既存登録は元フォルダー全体を別の検証用フォルダーにコピーしてから試します。

## 短い受入確認

本人が本当に使う10件ほどで、次を確認します。汎用サンプルだけで使いやすいと判断しません。

- 定番を呼出→選択だけで開ける。名前を入力したら目的の登録が先頭に来る。
- 直接登録と連携の.lnk/.urlが同じ検索で見つかり、正しい起動方法で開く。
- 新しい項目は追加直後に見つかり、保存時には起動しない。重複drop・保存失敗も確認する。
- 任意の組合せは対象数を確認してから開き、単独項目を選んだ場合はそれだけ開く。
- 読込中に検索、Esc、再表示、登録元解除・変更を繰り返しても、選択のすり替えや勝手な再表示がない。
- 既存のタスクバー、Quick access、ブラウザーブックマークより探す場所や余分な操作が減ったか比較する。

この比較で利得がなければ、機能を追加する前に方向性を見直します。
