# 非表示ランチャーの確認・復帰・終了

対象: 1.1.3-preview.1 / Windows 10・11。MSIの通常ビルド版は1.1.3。旧版の固定バーはこの版では生成しません。トレイアイコンは表示します。Windows側のピン留め・自動起動・セキュリティ設定を変更しません。

## 使い方

1. DHub.exeを起動する。通常は画面もタスクバーボタンも出ません。通知領域にDHubがあれば待機中です。Windowsの通知領域で隠れている場合は「隠れているインジケーター」を開きます。
2. Ctrl+Shift+Spaceで一覧を表示。文字を入力して絞り込み、Enterまたはダブルクリックで選択項目を開きます。
3. 選択・Esc・他の画面へ切替で一覧を隠します。一覧自体はタスクバーに表示しません。
4. 一覧下部「管理」またはCtrl+Shift+Dで管理画面。「キー設定」で呼び出しキーの変更。「終了」で常駐も終了します。
5. トレイの左クリックでも、お気に入り、検索、管理、設定、終了を選べます。管理画面の×は隠すだけで、常駐は続きます。明示的に開いた管理画面もタスクバーボタンは出さず、再表示はトレイまたはCtrl+Shift+Dから行います。

## キーが反応しないとき

登録に失敗した場合はキー設定の復帰画面を表示します。トレイにも登録失敗を表示します。

- 一覧キー候補: Ctrl+Shift+Space / Ctrl+Alt+Space / Ctrl+Alt+D
- 別の候補を選び「保存して適用」。その場で再登録します。他のアプリが同じキーを使う場合は別候補を選んでください。
- 競合するアプリを閉じた後は「今回だけ適用 / 再試行」でも再登録できます。このボタンは永続設定を変更しません。
- 管理用Ctrl+Shift+Dも登録結果を個別に表示します。管理キーだけが使えない場合も、トレイや一覧下部の「管理」は使用できます。
- 設定でホットキーを無効にした場合はトレイと再実行から戻れます。
- 保存データの不整合などで読み取り専用になっていても、キーの今回だけの再登録と終了は使用できます。永続変更は保存データを復旧してから行います。

復帰コマンド（PowerShell）:

```powershell
& 'C:\path\to\DHub.exe' --show
& 'C:\path\to\DHub.exe' --settings
# 独自保存先なら必ず同じパスも指定
& 'C:\path\to\DHub.exe' --data-dir "$env:TEMP\DHub-Preview-QA" --settings
```

既に動作中なら同じWindowsユーザー・セッション・保存先のプロセスへ表示要求を送って、二つ目は終了します。通信が失敗した場合は理由とトレイからの復帰方法を表示し、データやロックを削除しません。別セッション・パスの別名・異なる昇格レベルなどでは転送できないことがあります。別の保存先へ勝手に切り替えません。

## データの扱い

- 旧ShowLauncherBar・StartMinimizedToTray・ShowHomeOnStartupとバー位置は、読み込み・書き出し時に保持しますが、通常起動の表示には使いません。移行のためだけに保存を書き換えません。
- お気に入り、並び順、起動引数、開くアプリ、登録元フォルダーはそのままです。
- 新しいQuickSearchHotkeyは省略時Ctrl+Shift+Space。未対応の文字列は固定の既定キーへ戻して解釈し、コマンドとして実行しません。
- 既存のprofile排他、preview/stable保存先分離、保存回復ルールを維持します。IPCは同一user/session/profileの「一覧」「キー設定」だけを受け付け、ファイルパスや任意コマンド・終了要求は受け付けません。

## Windowsでの受入確認（自動検証とは別）

空のテスト用保存先で行い、実データを直接使わないでください。

- 新規・旧ShowLauncherBar=true・旧概要表示=trueの各profileで通常起動。メイン画面やバーが一瞬も出ず、トレイだけになる
- ホットキーで一覧が前面に出て検索欄に入力できる。選択・Esc・画面外クリックで隠れる。連打や押しっぱなしで多重表示しない
- トレイメニューを開いたままホットキーを押しても、トレイが閉じて一覧に入力できる
- 同じprofileで再実行 / --show / --settings。プロセスとprofileロックは1つのまま、既存ウィンドウが表示されて操作できる
- 別のテストprofileは独立。プレビューと通常版の保存先は混ざらない。キーが競合する側には明示的な回復画面が出る
- キー競合を起こし、別キーへ変更→保存→再起動で維持。再試行だけなら次回は保存済みキーに戻る
- 読み取り専用profileでもトレイ・キー復帰・終了は使える。登録データに新たな書き込みをしない
- 管理画面を開いて×で閉じ、再度表示する。最初だけ隠れる現象がない
- 管理の一般設定→キー設定→終了で、背後の設定画面も閉じてプロセスが終了する。すぐ再起動してもロック/pipeが残らない
- 一覧・トレイ・キー設定の各「終了」を確認。終了直前のキー連打や再実行で画面が残らない
- 既存お気に入り、順序、引数、バー位置値を前後で比較。サンプル追加でバーが再出現しない

## 自動検証の範囲

HiddenLauncherRegressionは引数・profile/user/session識別・キー登録失敗adapter・固定IPC protocolと、Windows上では実pipeの送受信、無効/部分要求、タイムアウト、終了・再起動を検証します。既存Storage/Launcher/Updater/ProfileImportの回帰も継続します。

クラウドの.NET8で行うlogic-only検証はWPF、Windows RegisterHotKey、実フォーカス、OSトレイ、WinFormsの終了動作を検証しません。GUI受入確認の完了と混同しないでください。Windows CIの実pipe/ビルド/MSI結果は対象commitのActions結果を確認してください。
