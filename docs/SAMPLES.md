# サンプルと起動画面（1.1.2-preview.1）

## 最初に試す

1. 新しいソースから `Build.cmd` でビルドし、新しい出力先の `Launch-Preview.cmd` を開きます。詳細は [LOCAL_CHECK.md](LOCAL_CHECK.md)。以前の出力先は更新されません。
2. 「作業の概要」が開いた場合は、先頭の青い **「ブックマーク一覧へ（次回も一覧から）」** を押します。次回の起動画面も一覧へ変更して保存します。
3. 一覧上部の **「サンプル3件を追加」** を押し、内容と保存先を確認します。概要・設定メニュー・トレイの管理メニューにも同じ入口があります。
4. 追加された固定バーのボタンを1回クリックして開きます。追加しただけでは、ファイル・フォルダー・Webサイトは開きません。

| サンプル | 実体と用途 |
|---|---|
| サンプル: 使い方メモ | `Samples\GettingStarted-v1\使い方メモ.txt`。テキストを既定アプリで開く例。短い使い方と削除方法を記載。 |
| サンプル: 作業フォルダー | `Samples\GettingStarted-v1\作業フォルダー`。説明テキストを含む実フォルダーを開く例。 |
| サンプル: Windows ヘルプ | `https://support.microsoft.com/ja-jp/windows`。Microsoft公式サイトを既定ブラウザーで開く例。自分でクリックしたときだけアクセス。 |

サンプルの保存先は**利用中のprofile内**です。既定のPreview保存先は `%LOCALAPPDATA%\DHub-Preview`。`Launch-Preview.cmd` では、そのビルド出力内の `preview-profile` を使います。

新しく追加した3種類の登録をお気に入りにし、既存の並びの末尾へ置きます。固定バーは今回の起動中だけ表示します。次回も表示したい場合は **「固定バーを表示」** を選びます。以前に保存した表示・位置設定はサンプル追加では変更しません。既存の同じ起動方法を利用する場合、その登録を勝手にお気に入りにはしません。

## 概要は任意

日常の入口はブックマーク一覧・固定バー・トレイの左クリックです。新規profileでは概要を自動表示しません。

概要には最近使った登録、作業セット、コマンド、ログをまとめて見る用途があるため、設定メニューの **「作業の概要（任意）」** に残しています。「今日」という名称や日次の必須作業という扱いはなくしました。

既存profileで明示保存された `ShowHomeOnStartup=true/false` と常駐起動の設定は維持します。概要先頭の青いボタンで、一覧起動に1操作で変更できます。設定画面の「起動時に作業の概要を表示（任意）」でも変更できます。設定保存に失敗した場合は画面上の値を戻し、保存状態の確認を案内します。

## 再追加・編集・削除

- 追加は明示操作時だけです。起動時の自動サンプル投入や既存登録の置換は行いません。
- サンプルには固定IDを使います。名前・起動先・メモ・お気に入りを自分で変更しても、再追加で置き換えたり重複させたりしません。
- 同じ種類・起動先・引数・開くアプリ・開くアプリの引数がある場合も追加を省きます。別の起動方法は独立した登録として残します。フォルダーの空の開くアプリと `explorer.exe` は、実際の起動処理と同様に既定の同じアプリとしてサンプル追加時だけ比較します。引数の違いは無視しません。
- 既存サンプルテキストを上書きしません。書き加えたメモはそのままです。元のサンプルファイルを自分で削除した場合は、次の明示追加時に不足ファイルを作り直します。
- 不要な登録は一覧で1件ずつ選び、**「削除」**。固定バーと作業セットの参照からも外れます。元ファイル・フォルダー・自分で追加した内容は削除しません。
- 登録だけを削除後、再び追加ボタンを押すと不足した登録を補います。既存の作業セットへ勝手に戻しません。
- バーからだけ外す場合は、ボタンを右クリックして **「バーから外す」**。登録は一覧に残ります。

## 保存・パスの保護

- 既存データの読み取り専用状態、読み込み後の外部変更、参照整合を確認してからサンプルを作成します。
- サンプルは専用の `Samples\GettingStarted-v1` 内だけに作成します。サンプルの保存先として検査するprofileルート・下位フォルダー・対象テキストに再解析ポイント（リンク等）がある場合は拒否します。既存ファイルがフォルダーと衝突する場合も拒否します。
- ファイルは `CreateNew` で作ります。利用者の既存文書や既存のサンプル内容を置き換えません。ファイル生成中のOSエラーでは一部の専用ファイルが残ることがあります。
- 登録はまとめて1回保存します。保存失敗時は追加した登録を画面上で取り消します。削除の保存失敗時は同じ登録オブジェクト・順番・作業セットの参照を戻します。
- 既存の統合JSON＋分離JSON保存は、複数ファイルを一括で原子的に置換する仕組みではありません。一部へ保存済みの場合に参照先を失わせないよう、失敗時も専用サンプルファイルは残します。「保存データの確認 / 復旧」で状態を確認してください。失敗した保存を自動再試行しません。
- ファイルシステムの検査と生成の間に別プロセスがパスを差し替える競合まで防ぐ保証はありません。通常のprofile排他と既存の保存保護を継続しています。

## 検証

Linuxの既設.NET 8 SDKを使う直接Roslyn試験で、実ソースの保存・サンプル114件、ランチャー55件、更新器59件が合格しました。更新器のWindows専用5件はスキップです。C# 12の構文検査とXAML XML・MainWindowハンドラー配線の静的検査も実施しました。別のLinux実ファイル検査で、profile・Samples・世代フォルダー・テキスト・作業フォルダーの直接リンク拒否を5件確認しました。Windowsのjunctionや実GUIの確認を代替するものではありません。

保存試験には新旧起動設定、3種類と永続化、重複・編集保持、同recipeの維持、通常削除と参照整合、読み取り専用・外部変更、ファイル生成失敗、保存失敗rollback、順序上限を含みます。

Windows CIでの.NET 10 WPFコンパイル・同梱runtime試験、実GUI・Shell起動・高DPIは、Linux試験では確認できません。分離JSONの途中保存後にOSが失敗するケースのサンプル専用障害注入は未実施です。次を隔離profileで確認してください。

1. 空のprofileは一覧＋説明。サンプル追加後に3ボタンをそれぞれ自分で起動できる。
2. 再追加して3件のまま。編集済みメモ・お気に入り解除・既存登録が変わらない。
3. 登録削除でファイルが残り、作業セット参照が外れる。再追加で不足登録だけ補う。
4. 終了・再起動で登録と順序が戻る。バーの保存済み表示設定を勝手に変えない。
5. 旧profileの概要から青いボタンで一覧へ進み、再起動後も一覧になる。
6. 読み取り専用・保存失敗では画面と参照が戻り、不明な保存状態を説明する。

MSIの既定バージョンは1.1.2です。`Test-Installer.ps1` の1.1.0→1.1.1→1.1.2はランダムなfixture ID・専用UpgradeCode・専用導入先を使う合成更新/rollback試験なので維持しています。本体MSIとの同一製品扱いにはなりません。
