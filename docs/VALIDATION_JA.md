# プレビューの確認手順

> 1.1.3-preview.1の通常起動では画面・固定バーを表示せずトレイで待機します。Ctrl+Shift+Space、トレイ、または同じ保存先のDHub再実行で一覧を呼び出してください。復帰・終了・受入確認は[非表示ランチャー](HIDDEN_LAUNCHER.md)を参照してください。通常MSIのビルド既定版は1.1.3です（回帰テストの1.1.0〜1.1.2は合成fixture）。


README の Windows + .NET 8 手順で、まず空の隔離した保存先を指定します。実データを使う場合はフォルダー一式をコピーし、元ファイルには触れないでください。

## 自動検証の範囲

2026-10-17 の Linux .NET 8.0.426 実行では、保存 85/85、ランチャー 24/24、更新器 50/50 が成功しました。production の C# ソースを test project に直接連結し、保存は一時フォルダーの実 IO、ランチャーは一時ファイルと監視、更新器は安全な合成パッケージ・置換失敗を検査しています。WPF / icon / Shell の境界は stub または注入した delegate です。実アプリの起動を検証した件数ではありません。

Windows CI は WPF 本体・Updater の clean build 後に同じ 3 スイートを実行します。[実行履歴](https://github.com/184649/DHub/actions?query=branch%3Acodex%2Fdhub-reliability-launcher-20261017) で対象 commit の結論を確認してください。初回 CI の Thickness 引数エラーは修正しました。

Linux では通常の SDK build が環境の NuGet migration mutex 制約で止まるため、package を追加せず SDK 同梱 Roslyn を直接利用しました。Windows の build / GUI の代わりにはなりません。

## Windows の手動チェック

1. 空の QA 保存先で起動し、管理画面・トレイ・終了が動くことを確認。
2. file / folder / URL / `.lnk` / `.url` を登録。存在するものだけ実際に開く。同じ exe の別引数、同名の別フォルダーも残ることを確認。
3. お気に入りを 21 件以上作成。トレイ左クリック→対象の 2 click、全件への導線、起動後も固定順を確認。menu を開く・hover するだけでは起動しないことも確認。
4. 一時フォルダーに階層と `.lnk` / `.url` を置き連携。階層、原フォルダーを開く、検索、非表示、解除を試し、元ファイルが残ることを確認。
5. popup を開いたまま合成ファイルを削除・同 path に再作成。古い行は再読込を促して直接起動を拒否することを確認。監視通知を受ける前の微小な競合を完全に防ぐ保証ではありません。
6. offline / 空 / 全非表示 / 検索 0 件を区別できること、登録済みの通常お気に入りが引き続き使えることを確認。
7. 検索画面で名称・recipe・tooltip が欠けず、閉じた後に再表示できることを確認。入力欄の Delete / Enter / Ctrl+C が一覧操作にならないことを確認。Memo 編集→保存→再起動で内容を確認。
8. Escape・矢印・Enter と popup 外クリックの閉じ方、元画面への focus 復帰を確認。100/150/200% DPI、複数画面、fullscreen でも試す。
9. 任意のバーを有効化し、トレイと順序・結果が同じことを確認。閉じた後の再表示、通常ウィンドウを妨げないことを確認。
10. 設定で分離保存を試す。アプリを閉じ、QA データだけを一部破損・欠損にして再起動。正常一覧が空にならず、読取専用・回復候補・差分が表示されることを確認。
11. 分離を OFF にした QA データに古い split を残して再起動し、古い内容が復活しないことを確認。
12. QA フォルダーへの保存が失敗する条件で起動を試す場合、OS の権限変更は別途判断してください。自動試験では失敗を注入済みです。要求成功後は「履歴保存失敗」と区別し、再保存がアプリをもう一度開かないことが合格条件です。

## 回復時に気を付けること

- 読取専用になるのは、破損・候補の不一致・外部変更・曖昧な保存失敗を検出した場合です。何もない新規 profile の状態とは区別します。
- 回復画面で candidate の差分を確認し、combined / split を選択します。保全先 `PreservedSnapshots` は通常 backup の整理対象外です。容量は利用者が確認してください。
- 再読込や候補の選択は未保存の編集・履歴を捨てる可能性があります。必要なら先にエクスポートします。エクスポートは memory snapshot、原本保全は元ファイル一式で役割が異なります。
- `BookmarkSources` は combined データに保存します。combined とその backup が両方失われ、split だけから回復する場合、フォルダー連携を再登録する必要があります。元フォルダーは残ります。
- 安全な保存は「検出済みの外部変更を上書きしない」方式です。複数プロセスや外部編集の未観測な同時変更を完全に排除する専用ロックではありません。

## フォルダー参照と更新の上限

- 走査は可視 10,000 件、深さ 16、訪問 20,000 件で打ち切ります。reparse point は辿りません。上限は状態表示し、取得済み全件検索と原フォルダーを開く入口を残します。
- 監視が利用できない、または source が消えた場合は古い snapshot の直接起動を停止します。再読込か原フォルダーを開く操作を使ってください。
- updater は公式 184649/DHub と既存 Chairman-bits/DHub の許可 URL、manifest にある必須 SHA-256 を使用します。古い hash のない manifest は安全側に拒否します。hash は発行者署名の代替ではありません。
- updater は準備完了を通知してから終了合図と対象 PID の終了を待ちます。強制 kill せず、失敗時は backup / rollback を保持します。実 Windows アプリ置換・再起動は未実施です。
- source build の preview は exe-only の通常版更新を拒否します。正式版は明示 version でビルドした self-contained package と manifest を揃えて別途検証してください。
